# JS API для сайтов Void Connect

Сайт в сети Void Connect — это каталог файлов (HTML, CSS, JS, картинки), который
раздают участники сети. С JS API такой сайт может больше, чем статическая
страница: знать, кто его открыл (с разрешения), хранить общие данные (посты,
комментарии, лайки), принимать файлы от пользователей и проигрывать видео с
перемоткой. Сервер для этого не нужен: данные подписывает каждый автор, и они
расходятся по сети между узлами.

Готовый пример — мини-видеохостинг **VoidTube** в
[`examples/sites/voidtube`](../examples/sites/voidtube). Опубликуйте этот каталог
на вкладке «Сайты» под именем, например, `tube` и откройте его.

## Подключение

```html
<script src="/.void/sdk.js"></script>
<script src="app.js" defer></script>
```

SDK отдаёт сам узел пользователя, скачивать его не нужно. После загрузки
доступен объект `window.Void`.

> **Inline-скрипты и `eval` запрещены.** Весь JavaScript держите в `.js`-файлах
> сайта. Внешние ресурсы из интернета (CDN, шрифты, счётчики) тоже не
> загрузятся: сайты сети изолированы от интернета, см. «Безопасность».

## Быстрый пример

```js
// Лента постов: общие данные сайта от всех авторов.
const posts = await Void.records.query('posts', { limit: 50 });
for (const p of posts) {
  const el = document.createElement('article');
  el.textContent = p.data.text;            // только textContent, не innerHTML!
  document.body.append(el);
}

// Написать пост: нужно разрешение publish (пользователь подтвердит в окне Void Connect).
await Void.requestPermissions(['identity', 'publish']);
await Void.records.put('posts', Void.newKey(), { text: 'Привет, сеть!' });

// Новые посты появляются сами.
Void.records.subscribe({ collection: 'posts' }, (rec) => console.log('новое', rec));
```

## Разрешения

Сайт сам по себе может только **читать** общедоступное: записи сайта, публичные
профили узлов, файлы сети. Всё, что делается от имени пользователя, требует его
согласия. Согласие даётся **в окне Void Connect**, а не на странице, поэтому
сайт не может подделать диалог или нажать «Разрешить» за пользователя.

| Разрешение | Что даёт |
|------------|----------|
| `identity` | `Void.me()`: ID, имя и аватар пользователя; поле `mine` в записях |
| `publish`  | `Void.records.put` / `delete`: записи, подписанные ключом пользователя |

Публикация каждого файла (`Void.files.upload`) подтверждается отдельно, каждый
раз: пользователь видит имя и размер файла.

Пользователь может отозвать разрешения на вкладке «Сайты». После отказа сайт
две минуты не может спрашивать снова (`code: 'cooldown'`).

```js
const granted = await Void.permissions();          // ['identity'] …
try {
  await Void.requestPermissions(['identity', 'publish']);
} catch (e) {
  if (e.code === 'denied') { /* пользователь отказал */ }
}
```

Пока ждёте ответа, SDK показывает внизу страницы подсказку «Подтвердите в окне
Void Connect». Отключить её можно так: `Void.config.consentHint = false`.

## Справочник

Все методы асинхронные (возвращают `Promise`). Ошибки — `Void.VoidError` с
полями `message`, `code`, `status` и `permission` (какое разрешение нужно).

### Сайт и пользователь

- `Void.site()` → `{ name, owner: { id, name, trust }, publishedAt, files }`
- `Void.me()` → `{ id, name, avatar? }`, нужно `identity`. `avatar` — `data:`-URI PNG.
- `Void.permissions()` → `['identity', 'publish']`
- `Void.requestPermissions(list)` → выданные разрешения
- `Void.profile(id)` → `{ id, name, avatar?, status?, description?, trust }` или `null`

`trust` — доверие к узлу глазами пользователя: `verified` (проверен лично),
`trusted` (через знакомых), `settled` (освоившийся), `stranger` (новичок).
Заблокированных пользователем узлов сайт не видит вовсе: их профили и записи не
возвращаются.

### Записи (общие данные сайта)

Запись — небольшой JSON (до 8 КБ), который подписывает автор. Адрес записи —
`(коллекция, автор, ключ)`: у каждого автора свои ключи, поэтому чужую запись
нельзя ни изменить, ни удалить. Записи одного сайта не видны другим сайтам.

- `Void.records.query(collection, opts)` → массив записей, свежие первыми.
  `opts`: `author`, `key`, `link`, `since` (новее, мс), `before` (старше, мс —
  для «загрузить ещё»), `limit` (до 500, по умолчанию 100).
- `Void.records.get(collection, author, key)` → запись или `null`
- `Void.records.put(collection, key, data, { link })` → записанная запись, нужно `publish`
- `Void.records.delete(collection, key)`, нужно `publish`
- `Void.records.subscribe({ collection, link, onResync }, onRecord)` → `{ close() }`

Запись:

```js
{
  collection: 'comments',
  key: 'lq3x9a-k2m4…',
  author: '9f3c…',          // ID автора (64 hex)
  updatedAt: 1763300000000,  // версия, мс
  link: '9f3c…:lq3x9a',     // необязательная ссылка для выборок
  data: { text: '…' },       // null у удалённой записи
  deleted: false,
  trust: 'trusted',
  mine: true                 // только с разрешением identity
}
```

Ограничения: коллекция — `[a-z0-9_-]`, до 32 символов; ключ —
`[A-Za-z0-9_.:-]`, до 64; ссылка — `[A-Za-z0-9_.:/-]`, до 128. `Void.newKey()`
даёт уникальный ключ.

**`link` — для связей.** Комментарии к видео храните с `link` = адрес видео и
выбирайте `query('comments', { link })`. Лайк — запись автора с ключом, который
зависит от видео (повторный лайк не создаст вторую запись), и тем же `link`;
число лайков — число записей.

**Живые обновления.** `subscribe` вызывает `onRecord` на каждую новую,
изменённую или удалённую (`deleted: true`) запись — свою и пришедшую из сети.
Если поток прервался или отстал, вызывается `onResync`: перечитайте данные
через `query`.

**Модерация.** Владелец сайта — `Void.site().owner.id`. Удобный приём:
владелец публикует записи в служебной коллекции (например, `hidden` со ссылкой
на скрываемое), а код сайта фильтрует ленту по записям только этого автора.
Так сделано в VoidTube.

**Лимиты.** Узел принимает от сайта до 30 записей подряд и дальше одну в
секунду (`code: 'rate_limited'`). Другие узлы ограничивают незнакомцев (новых
участников, за которых никто не поручился) сильнее: около 10 записей в минуту
и до 200 записей на сайт. Это защита от ботов, а не от обычных людей.

### Файлы

- `Void.files.upload(file, { name, onProgress, signal })` → `{ fileId, name, size, type }`.
  Пользователь подтверждает публикацию в окне Void Connect. До 4 ГБ.
- `Void.files.info(id)` → `{ id, name, size, type, playable, publisher, local }`
- `Void.files.url(id)` → адрес для `<video>`, `<audio>`, `<img>`, `<a download>`

Файл по `url` отдаётся с поддержкой Range: видео перематывается, а узел
докачивает у пиров только нужные куски. `local` — какая доля файла уже на
компьютере пользователя.

Безопасно (inline) отдаются только картинки (кроме SVG), видео, аудио и текст.
Остальное (HTML, SVG, PDF, скрипты…) браузер только скачает — такой файл нельзя
выполнить на адресе сайта.

## Безопасность

Как защищены пользователи и сайты:

- **У каждого сайта свой адрес** — `http://<имя>.localhost:<порт>/`, то есть
  свой origin. Браузер не даёт сайтам читать cookies, localStorage и данные
  друг друга; JS API узнаёт сайт по адресу, а не по словам страницы.
- **API отвечает только своему сайту.** Каждый вызов несёт заголовок
  `X-Void-Api`; запрос с другого сайта сети или из интернета без разрешения CORS
  его поставить не может, а `Origin` и `Sec-Fetch-Site` должны совпадать с
  сайтом. Защита от DNS rebinding — проверка Host.
- **Согласие только в окне приложения.** Кнопка «Разрешить» оживает не сразу,
  чтобы внезапный диалог не поймал случайный клик.
- **CSP**: скрипты — только файлы самого сайта, без inline и `eval`. Даже если
  сайт по ошибке вставит чужой комментарий через `innerHTML`, внедрённый код не
  выполнится. Запросы, картинки и шрифты — только с адреса сайта: сайт не может
  отправить данные пользователя на чужой сервер или подгрузить трекер.
- **Подписи.** Каждая запись подписана ключом автора, имя сайта входит в
  подпись. Узлы проверяют подпись, формат и размер записи и не дают одному
  автору занять больше своей квоты.
- **Сайтам никогда не доступны** ключи, личные сообщения, список контактов,
  файлы на диске и другие сайты.

Что остаётся на совести автора сайта:

- выводите чужие данные через `textContent` или `createTextNode`, а не через
  `innerHTML`;
- проверяйте поля записей: их пишет кто угодно (тип, длина, `data:`-префикс
  картинок и т. п.);
- не рассчитывайте, что запись «одна на пользователя» без проверки автора: один
  человек может иметь несколько ключей.

Известное ограничение: переход на внешнюю ссылку (`location = 'https://…'`) CSP
не запрещает. Поэтому ID пользователя сайт получает только с разрешения
`identity`.

## Как это устроено

```
страница сайта ──fetch /.void/api/*──▶ узел пользователя (127.0.0.1)
                                         │ разрешения, подпись записей
                                         ▼
                              SQLite: site_records ◀──── записи из сети
                                         │
                              чат-сеть: SiteRecord (живые записи),
                              SiteDigest/SiteRecordSync (сверка при связи)
```

Новые записи расходятся по сети сразу. При новой связи и раз в пять минут
соседи сверяют дайджесты (сводка по каждой паре «сайт, автор») и досылают друг
другу недостающее, поэтому узел, который был офлайн, догоняет остальных.
Файлы хранятся в обычном хранилище Void Connect кусками по 256 КБ.

Исходный код: `crates/web/src/api.rs` (HTTP API), `records.rs` (записи),
`security.rs` (заголовки и проверки), `sdk.js` (SDK), `ui/src/site_api.rs`
(синхронизация по сети), `ui/src/site_consent.rs` (диалог согласия).
